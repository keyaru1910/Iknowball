# Tái cấu trúc iKnowBall — Focus 100% vào Prediction

## Bối cảnh

API free không đủ quota để chạy đồng thời Standings + Live Scores + Predictions. Quyết định chiến lược: **bỏ phần Matches (lịch thi đấu / live scores) và Standings (bảng xếp hạng) khỏi giao diện người dùng**, tập trung toàn bộ quota API và effort phát triển vào **hệ thống dự đoán (Prediction)** — tính năng cốt lõi tạo giá trị khác biệt cho sản phẩm.

> [!IMPORTANT]
> **Không xóa backend data pipeline.** Hệ thống sync trận đấu, standings từ API bên ngoài vẫn cần hoạt động "ngầm" vì Prediction phụ thuộc hoàn toàn vào dữ liệu trận đấu để:
> - Tính Elo rating
> - Tạo feature snapshot (recent form, H2H, win rate...)
> - Đánh giá kết quả prediction (evaluatePending)
>
> Chỉ bỏ phần **hiển thị công khai** matches/standings trên frontend.

### Phase 3: Model Training + Backtesting (Phase cốt lõi)

> Từ Elo-v1 (rule-based) → Logistic Regression baseline (data-driven).
> Logistic Regression được tạo **module riêng** trong cùng prediction-service, không viết vào `main.py`.

#### [NEW] `prediction-service/app/models/logistic_model.py`
- Module riêng, cùng cấp với `elo_model.py` trong thư mục `app/models/`
- **Football**: 3-outcome Logistic Regression (HOME_WIN, DRAW, AWAY_WIN)
- **Basketball**: 2-outcome Logistic Regression (HOME_WIN, AWAY_WIN) — model tách riêng, không dùng chung
- Feature vector: `[elo_diff, home_advantage, form_diff, goal_diff_n, h2h_win_rate, ...]`
- Sử dụng `scikit-learn` `LogisticRegression` với `multi_class='multinomial'`
- Expose hàm `predict()` và `train()` tương tự interface của `elo_model.py`
- Lưu model weights bằng `joblib` (serialized file trong `prediction-service/models/`)

#### [NEW] `prediction-service/app/models/model_registry.py`
- Registry pattern: map `model_version` → model module
- `get_model(version)` → trả về module predict tương ứng (elo hoặc logistic)
- Giúp `main.py` gọi đúng model mà không cần import trực tiếp

#### [MODIFY] [backtest.py](file:///d:/iknowball%20project/prediction-service/app/evaluation/backtest.py)
- Thêm **walk-forward backtesting** cho Logistic Regression model (hiện chỉ có cho Elo-v1)
- **Không dùng random k-fold** (đúng như plan, tránh data leakage)
- Thêm evaluation metrics riêng theo từng class (đặc biệt DRAW)
- Output: **một con số performance đáng tin cậy** (Log Loss + Brier Score + per-class metrics)

#### [MODIFY] [metrics.py](file:///d:/iknowball%20project/prediction-service/app/evaluation/metrics.py)
- Thêm **per-class breakdown**: precision/recall/f1 cho từng outcome
- Thêm **calibration metrics**: reliability diagram data
- Thêm **comparison table**: Elo-v1 vs Logistic Regression vs Random vs Higher-Elo

#### [NEW] `prediction-service/notebooks/` — Jupyter notebooks
- `01_eda.ipynb`: Khám phá dữ liệu lịch sử, phân bố outcome
- `02_feature_engineering.ipynb`: Thử nghiệm sliding-window sizes
- `03_model_comparison.ipynb`: So sánh Elo-v1 vs LogReg, hyperparameter tuning
